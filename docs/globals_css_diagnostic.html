Critical — breaks in light mode
Critical
Mobile nav uses undefined --nav-bg variable
Line 472: .tn sets background: var(--nav-bg) but --nav-bg is never defined anywhere in :root or [data-theme="light"]. In dark mode this silently falls back to transparent (fine with backdrop-filter). In light mode the nav bar becomes invisible — you see the blur effect on nothing.
/* Add to :root */
--nav-bg: rgba(8, 12, 20, 0.8);

/* Add to [data-theme="light"] */
--nav-bg: rgba(237, 240, 245, 0.85);
Critical
GitHub social link hover hardcodes a dark-mode color
Line 2031: .sl.github:hover sets color: #e6edf3 — that's the dark theme text color verbatim. In light mode this renders near-white text on a white background on hover. Invisible.
color: #e6edf3;
color: var(--txt);
Critical
Modal overlay hardcodes a dark background
Line 1854: .ovl uses background: rgba(6, 9, 16, .85) — the raw dark bg hex. In light mode this still goes near-black correctly, but if the user changes --bg later the overlay won't track. More importantly it signals a pattern: raw hex leaks throughout when a variable should be used.
background: rgba(6, 9, 16, .85);
background: rgba(from var(--bg) r g b / .85);
/* Or simpler: */
background: color-mix(in srgb, var(--bg) 85%, transparent);
Critical
Bar track uses hardcoded dark-mode opacity
Line 907: .t-bar-track sets background: rgba(255, 255, 255, .06) — white at 6% opacity. On a light background this is invisible and gives the bar chart no track to read against.
background: rgba(255, 255, 255, .06);
background: var(--b);
Warnings — inconsistent or fragile
Warning
Achievement card tint uses hardcoded rgba against dark theme
Lines 1353–1365: .ach.gold, .ach.silver, .ach.blue all use raw rgba values for background and border (e.g. rgba(240, 183, 62, .03)). The .03 opacity barely shows in dark mode and does nothing in light mode. These should use your existing semantic variables like --acd, --bld, --pud.
Warning
Ambient glow effects (.bg-glow2, body::after) are dark-theme-only
Lines 127–148: The green and purple glows use raw rgba with dark-tuned opacity values (.055, .045). In light mode they're faintly visible but clash with the lighter background. Either hide them in light mode or drop their opacity significantly via [data-theme="light"] overrides.
[data-theme="light"] body::after,
[data-theme="light"] .bg-glow2 { opacity: 0.3; }
Warning
Dot grid pattern is dark-only (white dots on dark bg)
Line 120: body::before uses rgba(255, 255, 255, .055) — white dots. On your light bg (#edf0f5) these dots are still faintly visible but backwards (white dots on light grey). Switch to black-opacity dots in light mode.
[data-theme="light"] body::before {
  background-image: radial-gradient(circle, rgba(0,0,0,.04) 1px, transparent 1px);
}
Warning
.proj-status.active/.completed border uses raw rgba, not light-mode-aware
Lines 2343, 2350: Status badges use hardcoded rgba borders like rgba(0, 217, 126, .2) — the dark-theme accent hex. In light mode --ac changes to #00b366 but these borders don't follow it.
border: 1px solid rgba(0, 217, 126, .2);
border: 1px solid var(--acg);
Warning
.pt-btn.active glow uses box-shadow with hardcoded acg
Line 1690: box-shadow: 0 0 15px var(--acg) is fine, but on the light theme --acg at .22 opacity on a pale background makes a noticeable green smear. Consider reducing it in light mode or removing entirely.
Minor — polish items
Minor
.pill-st border uses blue rgba but color is --ac (green)
Line 753: The Statistics pill has color: var(--ac) (green) but border-color: rgba(88, 166, 255, .2) (blue). The pill is green-labeled with a blue border — mismatched. Should be rgba(0, 217, 126, .2) or just use var(--acg).
Minor
.mav gradient uses raw hex instead of variables
Line 1948: Modal avatar uses linear-gradient(135deg, rgba(0, 217, 126, .12), rgba(167, 139, 250, .1)). Works, but won't adapt if you ever tweak --ac or --pu. Use var(--acd) and var(--pud).
Minor
Syne font only loads weight 700 but is used at 800
Lines 15–21: The @font-face for Syne only declares font-weight: 700, but it's a variable font loaded as Syne-VariableFont_wght.ttf. Browser will synthesize 800 from 700, causing slightly blurry bold text on some engines. Fix: declare the full weight range.
font-weight: 700;
font-weight: 400 800;
